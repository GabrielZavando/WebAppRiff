## Why

The public site footer ships with placeholder/marketing copy that no longer matches what the client wants to publish: the `SERVICIOS` column lists generic services instead of the real offering, the `HORARIO TÉCNICO` column shows simplified hours (a single block per day range) instead of the real split-shift schedule (morning + afternoon blocks), and its column title is hardcoded inside the component instead of being part of the typed props contract like the other columns. In addition, the client wants explicit developer attribution rendered as a thin full-width strip directly below the footer, and asks for the site scrollbar to be tinted with the brand's dark navy (`#16202E`, which is exactly the existing `--color-secondary-dark` design token) so the global chrome feels branded. All four edits concern shared chrome rendered by `Layout.astro` on every page, so they are best handled as a single coherent change.

## What Changes

- **Footer schedule column title is promoted to config.** `Footer.astro` currently hardcodes `"HORARIO TÉCNICO"` on line 122. The title becomes a new `scheduleTitle` field in `SiteFooterProps` / `SITE_FOOTER_CONTENT` with the value `"Horario de Atención"`. It continues to render with the existing `uppercase` class (so the visible label reads `HORARIO DE ATENCIÓN`), keeping consistency with the `SERVICIOS` / `EMPRESA` column titles that already come from config. This establishes a single source of truth for every column title.
- **Footer schedule entries support multiple hour blocks per day range.** `FooterScheduleEntry.hours` changes from `string` to `readonly string[]`. The `<dl>` block is updated to render one `<dt>` (day range, white, semibold) followed by N `<dd>` rows (each hour block, muted), instead of a single `<dd>` per entry. The config is updated to the client's real split-shift schedule:
  - Lunes a Jueves: `9:00 a 13:00 hrs.` and `14:00 a 18:00 hrs.`
  - Viernes: `9:00 a 13:00 hrs.` and `14:00 a 17:00 hrs.`
- **Footer `SERVICIOS` links are replaced.** The four placeholder links become the real service offering: `Medición en Edificios`, `Medición Industrial`, `Obras y Proyectos`, `Tratamiento de Agua y Desalinización`. They keep the placeholder `href="#"` (real routes remain a future navigation change, design.md § Decision 5). The `EMPRESA` column is untouched.
- **New `SiteCredits` strip below the footer.** A new dumb presentational component `SiteCredits.astro` renders a thin full-width strip directly under `<Footer/>` in `Layout.astro`, with the text `Diseñado y desarrollado por: Gabriel Zavando` where `Gabriel Zavando` is an external link (`<a target="_blank" rel="noopener noreferrer" href="https://gabrielzavando.cl">`). The link is never underlined (including on hover) and animates subtly on hover using only design-system color tokens (`text-primary` → `text-primary-light` with a short `transition-colors`). The strip uses the flat-design conventions of the rest of the chrome: no `rounded*`, no `shadow*`, and only design-system background/text tokens. Its content is sourced from a new typed config (`SITE_CREDITS_CONTENT`) and a new `SiteCreditsProps` contract — the component is purely presentational and receives all data via props, mirroring the `Footer` contract.
- **Site scrollbar is tinted with the `--color-secondary-dark` token.** A scrollbar style block is added to `apps/web/src/styles/globals.css` (`@layer base`, alongside the existing `html` / `body` rules) styling only the thumb and the thumb:hover state, leaving the track transparent. The `#16202E` value is consumed through the existing `var(--color-secondary-dark)` token (no raw hex literals in CSS that lives outside the `@theme` definition, per frontend-standards § "Queda prohibido usar literales hex"). The thumb:hover uses `var(--color-secondary-light)` for a subtle but on-brand hover feedback. Coverage targets both the standard scrollbar-color property (Firefox) and the `::-webkit-scrollbar*` pseudo-elements (Chromium / Safari) for cross-browser parity, and respects the flat-design radius-0 rule.

## Capabilities

### New Capabilities

- `site-credits`: A thin full-width attribution strip rendered by `Layout.astro` directly below the global `site-footer`, containing the developer attribution text and a never-underlined external link to the developer's site, animated subtly on hover with design-system color tokens only, and following the same flat-design + dumb-component contract as the footer.
- `site-scrollbar`: The public site's global scrollbar is tinted with the brand's `--color-secondary-dark` design token (thumb + thumb:hover only; transparent track), applied via standard `scrollbar-color` and `::-webkit-scrollbar*` rules in `apps/web/src/styles/globals.css`, compliant with the no-raw-hex and radius-0 conventions.

### Modified Capabilities

- `site-footer`: Three requirement-level changes — (1) the schedule column title is no longer hardcoded in the component; it is a typed `scheduleTitle` prop sourced from config (`"Horario de Atención"`); (2) `FooterScheduleEntry.hours` becomes `readonly string[]` and the schedule `<dl>` renders multiple `<dd>` blocks per `<dt>` to support split-shift schedules; (3) the `SERVICIOS` column link labels are replaced with the four real services while keeping `href="#"`.
